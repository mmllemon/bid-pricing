# 正式用户产品开发文档、实现路线与任务清单

## 1. 产品目标

把现有“可验证的报价计算内核”升级为造价人员可直接使用的报价分析工具：用户上传两份固定格式 Excel，输入总报价和必要口径，系统自动识别、匹配、校验、计算、比较方案并输出报价 Excel。

## 2. 推荐产品架构

```text
┌──────────────────────────────┐
│ 用户界面                       │
│ 上传 / 参数 / 方案 / 异常 / 导出 │
└───────────────┬──────────────┘
                │ Application Service
┌───────────────▼──────────────┐
│ 项目会话层                     │
│ ProjectSession / QuoteScenario │
│ 版本、快照、审计、状态管理       │
└───────┬─────────┬─────────────┘
        │         │
┌───────▼──────┐  ┌▼────────────────┐
│ Excel 导入层   │  │ 口径与参数层      │
│ 模板识别       │  │ 税、固定费、隐形成本 │
│ 字段映射       │  │ 约束、方案参数      │
│ 清洗匹配       │  │                  │
└───────┬──────┘  └────────┬─────────┘
        └──────────┬────────┘
                   ▼
          ┌──────────────────┐
          │ 统一报价数据模型   │
          │ QuoteItem / Cost  │
          │ QuotePolicy       │
          └────────┬─────────┘
                   ▼
          ┌──────────────────┐
          │ Phase 1 + Phase 2 │
          │ 求解、复核、对拍     │
          └────────┬─────────┘
                   ▼
          ┌──────────────────┐
          │ 结果、对比、Excel   │
          │ 风险提示、审计快照    │
          └──────────────────┘
```

原则：界面不直接操作 `Phase1Instance`，所有计算经过应用服务层；所有用户输入先形成版本化 `QuotePolicy`，再传给求解器。

## 3. 核心数据模型

### 3.1 清单行

```text
QuoteItem
  project_id
  unit_work
  item_id
  item_name
  unit
  q0                  # 限价清单工程量
  q1_point            # 成本清单/结算预期工程量
  cap_excl_vat        # 不含税最高限价，空 = 无最高限价
  cost_input_incl_vat # 成本清单原始含税成本
  cost_effective      # 按税口径转换后的求解成本
  no_cap
  cost_missing
  provenance
```

### 3.2 项目口径

```text
QuotePolicy
  target_total
  fixed_pretax
  vat_rate
  surtax_rate
  cap_tax_scope = EXCL_VAT
  cost_tax_scope = INCL_VAT
  cost_input_vat_rate
  input_vat_credit_mode
  hidden_cost_policy
  loss_allowed
  unit_price_resolution
```

### 3.3 方案

```text
QuoteScenario
  scenario_id
  target_total
  fixed_cost_overrides
  hidden_cost_overrides
  tax_overrides
  constraints
  result
```

## 4. Excel 导入流程

### 4.1 限价清单

固定读取：项目编码、项目名称、计量单位、工程量、综合单价。

规则：

- 综合单价有值：作为 `cap_excl_vat`；
- 综合单价为空：`no_cap=true`，不是 0，不判异常；
- 综合单价为 0：单独提示“明确零价”，不能等同于空白；
- 缺编码、缺工程量、重复编码：阻断；
- 表头不匹配：阻断并提示模板版本或字段位置。

### 4.2 成本清单

固定读取：项目编码、项目名称、计量单位、工程量、综合单价。

规则：

- 综合单价作为 `cost_input_incl_vat`；
- 空成本：阻断该行进入最优求解，并列入待补成本清单；
- 成本为 0：提示确认是否为真实零成本；
- 成本清单与限价清单只按复合键匹配，不按序号匹配。

### 4.3 导入后必须展示的异常

| 异常 | 级别 | 默认动作 |
|---|---:|---|
| 文件格式错误 | BLOCKED | 停止 |
| 缺关键列 | BLOCKED | 停止 |
| 重复复合键 | BLOCKED | 停止 |
| 仅限价侧存在 | WARN/BLOCKED | 需补成本或排除 |
| 仅成本侧存在 | WARN | 确认是否新增项 |
| 无最高限价 | INFO/WARN | 允许继续，结果备注 |
| 成本税口径未确认 | BLOCKED | 停止求解 |
| 工程量缺失 | BLOCKED | 停止该行/项目 |
| 单价解析失败 | BLOCKED | 停止 |

## 5. 隐形成本处理方案

### 5.1 直接成本

按清单项录入，直接进入 `cost_effective`。

### 5.2 可分摊成本

用户选择分摊基数：人工费、直接成本、产值或自定义基数，并填写费率。系统必须显示分摊明细和分摊后成本。

### 5.3 项目固定成本

业务费、公司管理费、融资费等如果无法合理归属清单项，应录入“项目固定成本”，进入总价分解；它会减少总利润，但不会人为改变清单项的排序。

### 5.4 缺失成本的处理

不允许默认填 0。可选策略只有：

1. 补充成本后求解；
2. 标记为非竞争项并从优化域排除；
3. 用成本区间做情景分析，输出利润上下界。

## 6. 方案对比功能

第一版支持以下方案：

1. 保守方案：所有清单尽量接近成本/风险边界；
2. 利润最大方案：当前联合优化结果；
3. 均衡方案：限制单项利润率或报价离散度；
4. 无上限清单高配方案：允许无最高限价项目承担更多报价；
5. 成本上浮情景：材料/人工/管理费按比例上浮。

每个方案必须展示：总报价、竞争部分、利润、利润率、亏损项数量、无上限项数量、风险项数量、与基准方案的差异。

## 7. 分阶段实现路线

### Phase A：口径和数据模型修正（P0，1 周）

- 完成成本含税→有效成本的转换规则；
- 更新 `basis_declarations.json` 和成本字段语义；
- 增加进项税抵扣方式字段；
- 增加隐形成本模型；
- 增加空白最高限价的结果提示字段；
- 为所有新口径增加单元测试和回归样例。

验收：含税成本、不含税限价、不可抵扣税、空限价四类样例均能得到明确结果。

### Phase B：固定格式 Excel 导入服务（P0，1 周）

- 建立模板版本和字段位置配置；
- 实现上传文件哈希、版本识别、预览；
- 统一限价侧/成本侧导入；
- 完善异常分级和用户提示；
- 输出导入确认报告。

验收：用户只上传两份 Excel 即可完成识别和匹配，不需要手工改 JSON。

### Phase C：应用服务和正式界面（P1，2 周）

- 项目新建/打开；
- 上传限价清单、成本清单；
- 参数填写和校验；
- 异常确认页；
- 计算按钮、进度和结果页；
- Excel 导出和项目快照保存。

验收：不使用命令行，造价人员可独立完成一次完整报价。

### Phase D：方案管理和对比（P1，1 周）

- 保存多个方案；
- 修改总报价、固定费、税率、隐形成本后重新计算；
- 方案对比表和差异高亮；
- 一键复制方案。

验收：同一项目至少可同时保存并比较 3 个报价方案。

### Phase E：质量、审计和交付（P1，1 周）

- 全量回归测试；
- 真实 Excel 样本测试；
- 求解器和环境信息记录；
- 结果可复算校验；
- 安装/启动文档和用户手册。

## 9. 建议的下一步

下一步不应直接先做界面，而应先完成 **P0-01～P0-04**。原因是如果先做界面，用户看到的“利润”和“最优单价”仍可能建立在错误税口径或漏计隐形成本上，界面越完整，错误越容易被误认为正式结论。
