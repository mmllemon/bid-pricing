#### P0-0 的决定性发现：一道为防「静默失效」而建的门禁，自己静默失效了

接 P1-1 后去看 Actions，发现 **90 次运行、0 次成功**（最早 2026-10-07 09:35），
且早于本轮所有改动——这不是回归，是从未成立。

失败点只有一个：`Gate 0 机械判据`。但真正的问题是失败之后的事：

```
[failure] Gate 0 机械判据（Gate 0a）
[skipped] 契约制品完整性      ← 从没跑过
[skipped] 跳制品一致性          ← 从没跑过
[skipped] 规则集指纹自检        ← 从没跑过
[skipped] 全量测试              ← 从没跑过
```

GitHub Actions 默认「前一步失败则后一步 skip」。Gate 一红，后面四道**正交**判据
全被遮蔽。后果：本轮新加的三条守卫测试在 CI 里一次都没执行过——它们看起来
被「接进了 CI」，实际只接了个名字。

根因在字节层：`compute_artifact_hash` 对**原始字节**取 SHA-256，而开发者全局
`~/.gitconfig` 的 `core.autocrlf=input` 让 git 在提交时把 CRLF 转成 LF 存进索引。
工作树（CRLF）与仓库 blob（LF）字节不同：14 个受控制品里 **9 个**在干净检出
算不出注册表声明的 hash，Gate 0a/0b 双双 BLOCKED。

两条关键定性：
1. 逐字节核对确认这 9 项**内容级失配为 0**，差异纯行尾——里面**没藏着**「有人改了
   冻结制品却没重冻」的真篡改。这决定了修复可以安全地走「保字节」而不是「重冻」。
2. `config/gate0_registry.json` 的 approvals 块记录着四角色 2026-09-17 签署的制品 hash
   （如 `pricing_rule_card.json: sha256:d88298683924`）。那些字节**在版本库里并不存在**——
   git 擅自改写了被签名的内容。按 ADR-0018「审批签署具名制品」的口径，这不是小事。

**为何取方案 A（保历史 hash）而非 B（归一化行尾后重冻）**：A 只修 git 的字节保真，
不动注册表、不动签署记录，审计链零改写；B 会让 9 个制品 hash 全变，连带动到
四角色签署，等于要求重新走一轮审批——**改审计史不该由代理替用户决定**。

**修复与验证**（均在干净 worktree 实跑，worktree 已删）：

| 判据 | 修前 | 修后 |
|---|---|---|
| Gate 0a / Gate 0b | BLOCKED / BLOCKED | **PASS / PASS**（Phase 0 准入 RELEASED）|
| 契约制品完整性 | 从未执行 | **0 失配 / 0 SKIP** |
| 跳制品一致性 | 从未执行 | **PASS 17/17** |
| 规则集指纹自检 | 从未执行 | **PASS**（含 SEGMENT 退化遗留项如实输出）|
| 全量测试 | 从未执行 | 1660 项，与主仓一致 |

新增 `tests/test_artifact_byte_fidelity.py`（7 项）：把「干净检出可复现 hash」变成本机
提交前就能跑的判据，不必再等 CI 打脸。它同时钉 A（HEAD blob hash）与 B（text 属性
必须 unset）——**只看 A 会漏**：无 `-text` 时 `git show` 给的是存储 blob，checkout 会按
autocrlf 再转一次，此刻相等而检出后不等。另钉 `.gitattributes` 自身顺序（它也是手工
清单；写反过一次，git 属性后匹配者胜，保护会静默失效）。

反向验证：① 把 `-text` 段挑到通用段之前→ `check-attr` 解出 `text: set`，守卫红；
② 改注册表声明 hash → 红；③ 工作树多加一个字节 → 红；全部还原后 exit 0。

过程中还犯了一次该被记下来的错：我给 `run.ps1` 先写了注释说 `-text`、却漏写规则，
又先写了 `eol=crlf`——那会在下次 checkout 时无谓改文件。两处均由 `check-attr` 接回。

> **一句话教训**：任何「只在某台机器上成立」的结论，都必须有一条能在干净检出
> （或等价物）上跑的判据相配。否则它不是已验证，只是未暴露。
