# ADR-0001：三层分割架构（Phase 1 / Phase 2 / Phase 3）的地位

- **状态**：已采纳（accepted）
- **对应任务**：T00-05
- **机器可读版本**：`config/architecture_decision.json`
- **来源**：《模型设计 v0.3-R2》§7；《实施路线 v3.2.1》T00-05

## 背景

模型把求解分为三层：

1. **Phase 1** — 解析解（排序 + 二分 + 贪心定容），$O(n\log n)$；
2. **Phase 2** — 精确解（LP / MILP 分叉）；
3. **Phase 3** — 验证（独立复核）。

若 Phase 1 被当作"最终解"，则一个仅在其适用子集内成立的解析结论会污染整个定价决策。
路线 §4.1 的证伪实验（Phase 1 与 Phase 2 一致性）只有在 Phase 1 的适用条件被**形式化证明**
（T04-00）之后才配得上"数学等价性实验"这一名称。

## 决策

| 项 | 取值 |
|---|---|
| `phase1_role` | `candidate`（候选解 / 上界，**不等同 warm-start**） |
| `phase1_use_as_mip_start` | `false` |
| 最终解职责 | 由 Phase 2 承担 |
| Phase 3 独立性 | 禁止复用 Phase 2 的 $R_i$ / constraint / objective 实现 |

## 理由

1. **未证精确的解不应注入求解器**。把 Phase 1 结果作为 MILP 的 mip start，
   会使求解器从该点出发搜索；一旦该点违反真实可行域，剪枝路径被污染，
   而"求解成功"的结论看上去仍然成立——错误被静默。
2. **保留开关而非硬编码**。`phase1_role` 与 `phase1_use_as_mip_start` 均为可配置项，
   便于后续在有充分基准数据时重新评估。
3. **共因错误必须靠架构消除，而非靠流程**。若 Phase 3 复用 Phase 2 的目标函数实现，
   两条路径共享同一处错误，"对拍通过"只是同一错误的两次复现。
   因此 T04-08 要求三层隔离证明（源码文件不重叠 / 不共享可变状态 / 不由同一作者单人完成），
   并在验收未通过时把对拍结论强制标 `BLOCKED`。

## 后果

- **正面**：Phase 1 的性能优势（$O(n\log n)$）得以保留，同时其结论不被误用为最终解。
- **负面**：Phase 2 必须真实求解，不能靠 Phase 1 结果"验算通过"来跳过；
  求解时延基线须按 §8.1 建立 $P_{50}/P_{95}$，MILP 情形（C7 引入二元变量）须走 T04-07 协议。
- **约束**：Phase 3 需要**第二套独立实现**，人力成本约为单实现的 1.5–2 倍；
  这是路线明确接受的代价。

## 相关判据

- 判据 **S0**：目标函数独立重构，$|Z_{\text{solver}}-Z_{\text{ref}}|\le\epsilon_Z$
  ——"solver objective 正确 ≠ 业务利润正确"。
- 判据 **S5**：LP 与 MILP 分开验收；**禁止把 KKT 当作 MILP 的最优性证明**。
- 判据 **S7**：小规模基准 $Z_{\text{solver}}=Z_{\text{enumeration}}$（精确枚举比对）。
