# ADR-0004：「未定」必须是机器可判状态，不得用默认值兜底

- **状态**：已采纳（accepted）
- **对应任务**：T00-02 / T00-03 / T00-04 / T00-05 / T00-06 / T00-07（制品冻结机制）
- **实现**：`src/bidpricing/artifact.py`、`src/bidpricing/selection_options.py`
- **来源**：《实施路线 v3.2.1》§7.1.1 断言 1 / 4 / 6

## 背景

在一个"必须给出报价"的业务场景里，最危险的失败不是算错，而是**把"还没定"当成"已定"算下去**。
一旦某个口径处于未定状态而系统照常出数，用户拿到的是一个**看起来正常但依据悬空**的报价，
且错误不会以异常形式暴露。

路线 §7.1.1 列出了六条死锁断言，其中三条与"未定态"直接相关。
本 ADR 固化其工程实现方式——**为什么必须是这几种实现，而不是别的**。

## 决策

### 一、「未定」= key 完全缺失，而非 `null` / `"未定"` / `"UNDETERMINED"`

```json
// ✅ 正确：还没选
{ "rule_set_id": "GB/T50500-2024" }

// ❌ 全部错误
{ "rule_set_id": "GB/T50500-2024", "adjustment_scope": null }
{ "rule_set_id": "GB/T50500-2024", "adjustment_scope": "未定" }
{ "rule_set_id": "GB/T50500-2024", "adjustment_scope": "UNDETERMINED" }
```

**理由**：前两种写法会绕过「非空即通过」这类朴素校验。
`null` 与 `"未定"` 都是**非空字符串/非缺失值**，一个只检查"字段存在吗"的判据会放行它们。
只有让"未定"表现为 **key 不存在**，"还没定"才成为**机器可判**的状态。

代码侧对应 `gate0.guard_representation`，并对违规写法直接判 `BLOCKED`。

### 二、选择项**不设默认值**

注册表中 `default` 恒为 `None`；断言 6① 通过**静态扫描**拒绝配置文件里出现
`default` / `template` 字段。

**理由**：默认值的作用是"在用户未选择时替用户选"。但本模型的选择项
（如 `adjustment_scope`）**两种取值下最优报价结构相反、利润差约 4.5 倍**——
替用户选，等于替用户承担一个后果相反的决策。宁可 BLOCKED，不可默认。

### 三、制品的"已冻结"由内容 hash 绑定

每个受控制品带三个字段，由 `freeze` 命令写入：

```
_version / _hash / _frozen_at      hash = 制品内容 SHA-256 前 12 位
```

**理由**：制品一改，hash 失配，**闸门自动失效**。
这消除了"改了配置但忘了重新过闸门"这一失效模式——不需要任何人记得。

### 四、未完成制品自声明 `freeze_blocker`，冻结器拒绝写入 hash

若制品自身声明 `freeze_blocker`（如"待真实数据填入"），`freeze` 命令**抛
`ArtifactNotFreezable` 拒绝冻结**。

**理由**：防止"因为文件存在就获得 hash"，进而被闸门误判为"已冻结 = 已通过"。
**「文件存在」不等于「内容有效」。**

## 后果

- **正面**：三类失败（未定 / 未冻结 / 未完成）都有各自的机器可判形态，报告可精确归因。
- **正面**：`gate-check` 与 CI 共用同一套判据，本地通过即 CI 通过，不存在"本地能过 CI 不能过"。
- **负面**：用户必须显式落值，系统不提供"先用一个合理默认跑起来"的便利路径。
  这是**刻意接受的代价**——见 ADR-0002 的三时点分层：
  未定不阻塞开发（Gate 0a 判机制），只阻塞求解（Phase 0 输入门判取值）。
- **约束**：契约制品改动后必须重新冻结（`bidpricing freeze --all`），
  否则 hash 失配会让闸门失效——这是特性而非缺陷。

## 相关的三处易犯错误（实测踩过）

| # | 错误 | 正确做法 |
|---|---|---|
| 1 | 把"未定"写成 `null` 或 `"未定"` | 不写该 key |
| 2 | 为选择项补一个"合理默认值" | 不设默认；未定由 Phase 0 输入门拦 |
| 3 | 用制品存在性替代内容有效性 | 用 hash 绑定 + `freeze_blocker` 双保险 |
