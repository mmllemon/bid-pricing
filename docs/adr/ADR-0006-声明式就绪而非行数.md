# ADR-0006 声明式就绪，而非行数

- 状态：已采纳
- 日期：2026-09-16
- 关联：ADR-0002（判定时点与机制数据分层）、ADR-0004（未定态必须是机器可判状态）、T00-06
- 证据：`config/gate0_registry.json`、`src/bidpricing/gates/gate0.py::_check_project_input`、`tests/test_gate0.py::ProjectInputArtifactTest`（165 项测试全绿）

## 背景

ADR-0002 把 T00-06 拆成了两层：**规则书**（跨项目复用的机制，属 Gate 0a）
与**项目级落值表**（一项目一份的数据，属 Phase 0 输入门）。拆得对，但拆完之后
留下的判据是错的：

```python
min_rows = int(spec.get("min_rows", 1))     # 旧判据
if len(rows) < min_rows:
    return BLOCKED
```

2026-09-16 用户提出一个反直觉但正确的质疑：

> 如果没有特殊说明，分部分项清单里面的应都是可竞争项，所以为什么要做这个分类？

这个质疑暴露了两件事。

## 问题一：分类做过了头

分部分项清单里，除被标记的行之外，**其余缺省就是可竞争项**——这是清单计价
的基本性质，不需要逐行判断。而清单内的例外（`其中:暂估价` 列、甲供材）在清单里
**是列**，是机械可读信号，同样不需要人判断。

于是「分类」的真实必要性收缩到了分部分项清单**之外**，只有三处：

| 位置 | 角色 | 为什么必须分类 |
|---|---|---|
| 表-10 施工组织措施 | `NON_COMPETITIVE` | 费率式（有费率、无工程量、无综合单价），是安全文明施工费的**唯一落点** |
| 表-11 其他项目 | `PASS_THROUGH` | 暂列金额、暂估价按实结算，不竞价 |
| 规费、税金 | `NON_COMPETITIVE` | 汇总性外生常量，只接收金额不复算 |

要求人工对四张清单逐行填 `pricing_role` 属**过度设计**——大部分行的答案由
「所属清单 + 是否被标记」唯一确定。

**决定**：改为「**声明每张清单的缺省角色 + 登记例外**」。落值表的结构相应变为
`covered_lists`（缺省角色）/ `exceptions`（例外）/ `external_constants`（汇总性外生常量）。

## 问题二：判据把「结论为空」当成了「没做」（本 ADR 的核心）

行数判据 `len(rows) >= 1` 与 ADR-0004 属于**同一类错误**：它把两种机器上应当
可区分的状态混成了一种。

| 状态 | 含义 | 正确反应 |
|---|---|---|
| 表里 0 行 | 可能是「没做」，也可能是「做了且无例外」 | **无法区分** |
| `"exceptions": []` | **已核查，结论为空**（本标段无例外项） | `PASS` |
| `"exceptions"` key 缺失 | **根本没声明** | `BLOCKED` |

旧判据对前两者一视同仁地 BLOCKED，等于**用「没有例外」惩罚「认真核查过」**。

**决定**：判据改为**声明式就绪**——

1. **标量字段**（`project_id` / `code_system` / `search_basis`）：key 缺失或空值 → BLOCKED。
2. **列表字段**（`covered_lists` / `external_constants` / `exceptions`）：
   **key 必须存在**，但**取空列表是合法结论**。
3. 逐条校验覆盖声明的缺省角色、例外行的字段与角色、外部常量的取值与依据。

## 为什么不是「把 min_rows 改成 0」

因为那样会变成**空真通过**：一份 `{}` 也能过，判据等于被静默取消。
「允许空」与「允许缺失」是两件事——前者是结论，后者是没做。

判据保留了对**声明完整性**的要求：`search_basis` 必须非空。这一条是关键的
防呆——它让「无例外」成为一个**可复核的断言**（我按什么检索了、没找到），
而不是一句无从验证的空话。没有检索依据的「无例外」不构成结论。

## 后果

**正面**
- 人工成本从「逐行过清单」降到「确认例外清单」；清单越大收益越明显。
- 「无例外」与「没做」在机器上可区分，失败报告可归因。
- 与 ADR-0004 的「未定态 = key 完全缺失」形成同一条规则的两个应用点，
  减少再次踩同型坑的概率。

**负面 / 代价**
- 本判据只能校验**声明**是否就位；**逐行覆盖率无法在此校验**（无解析数据时
  不可判）。逐行覆盖率的校验落在 T01-00B 解析产物上（`Σ明细 == 表列小计`，
  见 ADR-0005 的输入保真判据），不复用本判据。这是**有意的职责切分**，
  不是遗漏。
- 声明与真实清单可能不一致（声明了却填错）。这由 T01-00B 的下游校验兜底，
  不在本判据内解决。
