# ADR-0007 沉默不是断言

- 状态：已采纳
- 日期：2026-09-16
- 关联：ADR-0004（未定态必须是机器可判状态）、ADR-0002（判定时点分层）、ADR-0006（声明式就绪）
- 证据：`config/input_protocol_schema.json` 的 `open_issues[OI-04].correction`、`docs/adr/ADR-0007`（本文件）、`src/bidpricing/contracts/consistency.py::_check_open_issues_naming`、`tests/test_contract_consistency.py::OpenIssuesTest`

## 起因：一句话被记反了

在把用户的真实输入形态写进契约时，记录了这样一条待决问题（OI-04）：

> `observed`: 用户明确：招标文件通常只限制「分部分项清单的各项单价」与「整个项目的总价」
> 不超过限价——**没有给出单价下限**。

用户随即指出：

> 招标文件只限上限、不限下限，**我没有这样说**。我的意思是招标文件有最高限价，
> 但是同时**单项报价不能为 0**，且**有些时候会有不平衡报价条款**作为约束，比如 ±50%。

「没有给出单价下限」这七个字，**用户从未说过**。它的来源是记录者的**外推**：
用户说过「只会限制①各项单价②总价」，记录者由此推出「所以没有下限」，
然后把这个推论**写成了用户的明确断言**。

## 这不是"记错了"，是一类结构性的失效

把「用户没提」写成「用户说了没有」，后果不是措辞不严谨，而是**模型少了一条约束**：

| 记录写法 | 下游后果 |
|---|---|
| 「用户明确：没有单价下限」 | C3 下界失去依据 → 建议标 `NOT_APPLICABLE` → **报价可以压到 0** |
| 用户真实意思：单项不得为 0 + 不平衡条款 ±50% | C5 是 P0 硬约束；另有 C13 条件性约束 |

两者在求解结果上差得很远：前者允许「个别项压至 0」这种工程上荒谬、评审上直接
触发清标的解——正是 C5 与 C6 存在的原因。**一条被记反的转述，删掉了一条 P0 约束。**

## 与 ADR-0004 同源

| | ADR-0004 | 本 ADR |
|---|---|---|
| 管的是谁 | **机器** | **人** |
| 未声明的形态 | key 完全缺失 | 用户没提 |
| 禁止的做法 | 写成 `null` / `"UNDETERMINED"` | 写成「用户明确：没有」 |
| 为什么禁止 | 「非空即通过」会绕过熔断点 | 「用户说了没有」会被当成已确认事实，**不再回头问** |

两条规则是同一条原则的两个作用面：**「未提及」与「已声明为无」是两种不同状态，
不得互相冒充。** 前者必须保持「未知」，直到有人真的作出断言。

差别在于：ADR-0004 的违例机器可以拦（`key` 在不在，一看便知）；
本 ADR 的违例机器**拦不住语义**，只能靠**留痕**让它可被复核。

## 决定

1. **不得把推论写成断言。** 记录用户口径时，凡用户未明说的部分，一律标注为
   「记录者外推」并列入待确认，**不得**以「用户明确」开头。
2. **被纠正的条目必须保留纠正留痕**，不得静默改写：
   `correction.what_was_wrong`（原来怎么写的）+ `correction.user_actual_words`
   （用户的原话）+ `correction.failure_mode`（归到哪条 ADR）。
   撤销一个结论时，**被撤销的那个结论本身也是信息**——它解释了为什么下游
   曾经按另一套口径设计过。
3. **机械可判的部分必须机械判**（`_check_open_issues_naming`）：
   - 标 `RESOLVED` 的开放问题必须带 `decision` 或 `clause_inventory`；
   - 带 `correction` 的条目**必须**记录 `user_actual_words`——没有原话，
     转述是否忠实就无法复核，纠错机制等于没有。
4. **同类问题的通用判据**（与前三条同源，用于识别将来会不会再犯）：
   > 凡是记录者需要**从用户话语中推出一个否定性结论**（「没有 X」「不适用 X」
   > 「不需要 X」）的地方，都必须在制品里留下**用户原话**，否则该结论不得成立。

## 后果

**正面**
- 契约里不会再出现「看起来像事实、实际是外推」的断言。
- 撤销的旧口径保留在制品中，接手者能看到「为什么这里曾经是另一种设计」。
- 与 ADR-0002 / 0004 / 0006 合成一组同源规则，四条的失效模式都指向同一个根因：
  **把两种应当区分的状态混成一种**（机制 vs 数据 / 未定 vs 已定 / 空 vs 缺 / 未提 vs 无）。

**负面 / 代价**
- 制品体积变大（纠正留痕 + 原话），`input_protocol_schema` 已增长至数倍。
  这是**有意的代价**：可复核性优先于紧凑。
- 判据只能校验留痕字段**存在**，不能校验留痕内容是否忠实——最后的防线仍是人。
