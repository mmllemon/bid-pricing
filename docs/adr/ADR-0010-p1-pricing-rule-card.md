# ADR-0010：P1 计算口径 re-base —— 计价规则卡与 ρ± 默认值的性质区分

- **状态**：已接受（2026-09-16）
- **关联任务**：T00-01《计价规则卡》、T00-08 规则集选择器
- **制品**：`config/pricing_rule_card.json`（`pricing_rule_card_v1`）
- **实现**：`src/bidpricing/contracts/pricing_card.py`、CLI `pricing-card`

---

## 一、背景：规则集定了，P1 仍未定

T00-08 解决了「用哪一版规范」，但**同一 rule_set_id 下 P1 怎么算仍是空的**：

1. 2024 §8.9.2 写「合理下调/上调**其合同单价**」，2013 §9.6.2 写「**重新确定**」——
   两版 P1 的**生成方式不同**，不是同一公式换条号；
2. 两版都写「合理」，**都没给量化系数**——ρ± 无规范依据；
3. 2024 未明说调整作用域是否分段（`adjustment_scope` 因此才是选择项）；
4. 合同专用条款（不平衡报价 ±50%、10.4.1.3 变更估价原则）**叠加在规范之上**，
   却一直以口头约定形式存在于对话里。

结果：WP3 判定层缺少可引用的参数来源，若直接开工必然在各模块各自硬编码阈值，
重演「同一规则两处说法」（13/15 位编码、`GBT50500-2024` / `GB/T50500-2024`
两种写法均属此类）。

## 二、决定

**引入《计价规则卡》制品，作为 P1 口径的唯一参数来源**，并回答 T00-01 要求的
五项澄清（P1-A ~ P1-E，全部 `RESOLVED`）：

| # | 问题 | 结论 |
|---|---|---|
| P1-A | P1 是「重新确定」还是「在合同单价上调整」？ | **ADJUST_ON_CONTRACT_PRICE**（2024 以 P0 为基数；2013 才是重新确定，与 P0 脱钩） |
| P1-B | ρ± 取多少？ | **0（默认）+ 敏感性扫描 [0, 0.15]** |
| P1-C | 15% 阈值的起算基准？ | **r = Q1/Q0**（工程量比，非金额比） |
| P1-D | 作用域？ | **SEGMENT**（项目级落值；减量侧 FULL/SEGMENT 等价） |
| P1-E | 减量侧对称吗？ρ⁺ 与 ρ⁻ 需相等吗？ | **对称成立；两系数独立取值**（成因不同：获得优惠 vs 失去优惠） |

### 关键区分：**ρ± = 0 是机制层默认，不是数据层缺省**

这是本 ADR 的核心。两种「取 0」在机器上同形、在语义上相反：

| | 机制层默认 | 数据层缺省 |
|---|---|---|
| 含义 | 规范未给系数 → **不编造**，按「不调整」计算基准解 | 项目本应声明的值还没填 |
| 可否静默使用 | **可以**，但输出必须声明来源 | **不可以**，必须 BLOCKED |
| 本模型写法 | `parameters.rho_*` + `rho_source` + `rho_default_is_mechanism_not_data` | 未定态 = key 缺失（ADR-0004） |

若把 ρ=0 当数据缺省，就会在报价表里声称「规范规定不调整」——**这是把未知
写成了已知**（ADR-0007：沉默不是断言）。规则卡因此强制携带
`rho_default_is_mechanism_not_data` 字段，测试断言其非空。

## 三、唯一事实源与双向锁定

阈值与分支名的真值在**代码常量**（`rule_sets.base.INCREASE_THRESHOLD` 等），
规则卡 JSON 只是**声明**。两侧由 `tests/test_pricing_card.py` 双向锁定：

- 声明值 ≠ 代码常量 → `PricingCardError`（「同一规则两处说法」）；
- `compute_p1()` 的结算金额与 `rule_sets.settlement_amount()` **逐值对拍**；
- 契约层新增第 12 判据（`consistency._check_pricing_card_selection`）：
  规则卡的 `adjustment_scope` / `contract_type` / `rule_set_id` 必须与
  `project_selection.json` / `project_classification_table.json` 一致——
  **改落值不同步规则卡即判矛盾**。

### 未定态与 override

- Q0 / Q1 / P0 任一缺失，或 Q0 ≤ 0 → **BLOCKED**，不降级为 0；
- 出现规则卡未登记的 override 键 → **BLOCKED**（已知键 + 未知键混用同样阻断，
  不是「用已知的那部分」）；
- 显式 `None` 的 override = 未声明，按卡片值处理（不是未知键）。

## 四、后果

- **WP3 判定层**可直接引用规则卡构造 `R_i(·)` 分段逻辑，不再各自硬编码阈值；
- **WP4/WP5** 的敏感性扫描区间由此固定：ρ± ∈ [0, 0.15]、
  不平衡报价修正价 p_rev ∈ [c_i, cap_i]（OI-06）；
- 规则卡纳入 Gate 0a 受控制品（`pricing_rule_card_version`），改字节即 hash 失配。

## 五、真实数据上的第一手结论（西永L，82 键）

`pricing-card --from-match` 对匹配报告逐项判分支：

```
IN_RANGE  75 项（92.6%）   ← 结算结构不随报价改变
DECREASE   6 项（ 7.4%）   ← P1 与不平衡报价条款的作用域
INCREASE   0 项（ 0.0%）
```

六项减量越界：`030414002003`(0.4286)、`030403006002`(0.5000)、
`030403006001`(0.6000)、`03B009`(0.6000)、`030413001001`(0.7225)、
`030408001003`(0.8031)。

**与 D07 亏损项的交集**：`030403006001`、`030403006002`、`030413001001`
三项既减量越界又成本倒挂——即「量要少了、还要亏着做」，是本项目最需要优先
复核的三项。

## 六、被否方案

| 方案 | 否决理由 |
|---|---|
| 阈值直接写进各 WP 模块 | 重演「同一规则两处说法」，且漂移只能靠人眼发现 |
| ρ± 由模型拟合历史数据得出 | 投标期无可靠样本；且等于用数据填补规范空白，与「不编造」冲突 |
| 规则卡复制项目落值（不再交叉校验） | 落值变更时规则卡必然过期，正是本 ADR 要消除的失败模式 |
