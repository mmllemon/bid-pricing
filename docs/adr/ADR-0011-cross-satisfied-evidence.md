# ADR-0011：附证交叉满足 —— 「没说」与「在别处说过」必须区分

- 状态：**已接受**（2026-09-17）
- 关联：ADR-0002（机制 vs 数据分时点判）、ADR-0004（未定态不得降级为默认值）、
  ADR-0007（沉默不是断言）、T00-11（c_i 假设声明书）

---

## 背景

T00-11 为每种 c_i 来源规定了强制附证（`required_when`）。用户声明
`SUPPLIER_QUOTE` 后，判据要求补齐三项：询价日期、品牌规格、含税/不含税口径。

其中**「含税/不含税口径」已在两处受控制品里声明过**：

- `config/basis_declarations.json`：cap / cost 两侧均 `EXCL_VAT`（用户 2026-09-16 亲述）
- `config/cost_basis_spec.json`：CB-04 判据，已 PASS

此时再向用户索取同一声明，是把**已定态**当成**未定态**处理。

## 决策

引入**附证交叉满足**机制：

1. `required_when` 保持为"该来源的完整附证清单"——清单本身不变，可审计性不减。
2. 新增 `cross_satisfied_by`：键为附证项，值为**本报告内的判据 ID**。
   该判据 PASS ⇔ 该项视为已满足，不再列入"仍缺"。
3. **交叉引用失效不得静默放行**：引用的判据不存在或非 PASS 时，退回要求显式附证，
   并在证据行标注"交叉引用失效：X→CB-99(未 PASS)"。
4. 死引用由测试拦截（`test_cross_references_point_to_real_rules`）：引用必须指向
   已知判据 ID，且该附证项必须原本就属于某个来源的 `required_when`。

## 为什么不是别的做法

| 备选 | 否决理由 |
|---|---|
| 让用户再声明一次税口径 | 同一事实两处录入，必然漂移；且制造告警疲劳，使真正的缺证（询价日期）被一起忽略 |
| 直接从 `required_when` 删掉税口径 | 删除后来源变更（如改为 `EXPERT_ESTIMATE`）时无从判断该来源是否该要这项——**清单是机制，满足方式是数据** |
| 自动从其它制品拷贝值进 `declared_evidence` | 复制即分叉；拷贝后原制品改动不会回流，且无法区分"用户说的"与"系统抄的"（违反 ADR-0007） |

## 与既有规则的关系

- **ADR-0002 的应用**：税口径是**机制层**口径（两侧同为不含增值税），机制层已定的
  口径不要求**数据层**重复声明。
- **ADR-0004 不冲突**：交叉满足不是"未定态降级为默认值"，而是"已定态的定态复用"。
  判据非 PASS 时立即退回显式索取，不存在静默补全。
- **ADR-0007 不冲突**：交叉满足引用的是**用户自己的既有声明**（basis_declarations
  由用户 2026-09-16 亲述），不是模型推断。

## 后果

- 正向：跨制品声明只说一次，杜绝同义重复录入导致的漂移。
- 代价：多一层间接引用，需要死引用测试守护（已加）。
- 现状：本项目「含税/不含税口径」由 `CB-04` 交叉满足；
  「询价日期」「品牌规格」为真实缺证，AS-02 保持 WARN，
  **补齐前不得冻结**（`cost-check --freeze` 带病拒冻）。
