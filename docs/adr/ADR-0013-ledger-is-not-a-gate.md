# ADR-0013：台账不是关卡 —— 区分「计算前提」与「来源留痕」

- 状态：**已接受**（2026-09-17）
- 关联：ADR-0004（未定态不得降级为默认值）、ADR-0007（沉默不是断言）、
  ADR-0008（五态语义）、ADR-0011（附证交叉满足）、ADR-0012（q1 是预测不是事实）

---

## 背景

用户提供了两份清单（招标限价清单 + 成本清单）后，我陆续建了三样东西并把它们
做成了**阻塞或告警项**：询价日期 / 品牌规格、算量依据（图纸版本）、扫描网格。

用户的质询（2026-09-17，**第四次同类质询**）：

> 「我既然给了你成本清单，你只需要按照我的成本清单数据来测算就行，
> 你说的那些什么声明书有什么意义」
> 「扫描网格是什么意思，不懂」

**用户是对的。** 逐项复核对算式的影响：

| 我做成关卡的项 | 实际影响 |
|---|---|
| c_i 来源（供应商询价） | 无——算式里只有 c_i 这个数，没有「它哪来的」 |
| 询价日期 / 品牌规格 | 无——纯留痕 |
| q1 取值依据（成本清单量） | 无——同上 |
| 算量依据（图纸版本） | 无——只影响结论能否被解释 |
| 敏感性分析 / 扫描网格 | 无——那是**分析能力**，不是**数据前提** |
| **格式（POINT/INTERVAL）** | **有**——点值与区间是不同的数学模型 |
| **数值本身缺失** | **有**——算式直接算不出 |

**真正必需的只有五样，用户全都给了**：q⁰、cap_i（限价清单）、q¹、c_i（成本清单）、
P\*（用户给定）。其余全是元数据。

## 决策

### 1. 新增第六态 INFO

校验层由五态（ADR-0008）扩为六态，新增 **INFO**：

> **INFO**：留痕项缺失——记录但**无需任何行动**，不影响计算，仅供将来复核与
> 责任划分。

INFO 不参与 `blocking` 判定（只 `BLOCKED` / `FAIL` 参与），因此不影响闸门。

### 2. 判断准则（唯一一条）

> 一个字段缺失会让**算式算不出或算错**，才配 BLOCKED；
> 只让结论**说不清出处**的，一律 INFO。

按此准则的降级结果：

| 判据 | 原 | 现 | 理由 |
|---|---|---|---|
| AS-01 c_i 来源未声明 | BLOCKED | **INFO** | 数值由字段字典 `missing_policy` 把关 |
| AS-02 询价日期/品牌规格 | WARN | **INFO** | 纯留痕 |
| QB-01 q1 取值依据未声明 | BLOCKED | **INFO** | 同上 |
| QB-03 算量依据（图纸版本） | WARN | **INFO** | 只影响结论可解释性 |
| QB-05 点值未做敏感性分析 | BLOCKED | **PASS**（默认） | 可选增强，默认关闭 |
| QB-06 扫描网格未定 | WARN | **SKIP**（未启用时） | 同上 |
| AS-03 / QB-04 格式一致性 | BLOCKED | **保留 BLOCKED** | 格式决定数学模型 |
| QB-02 归因 = UNKNOWN | WARN | **保留 WARN** | 归因决定报价方向（ADR-0012 附） |

### 3. 敏感性分析由「前提」改为「默认关闭的可选增强」

`mode = OPTIONAL_ENHANCEMENT`、`enabled = false`；用户此前选的 `RATIO_SCAN`
保留为 `preferred_method`。**模型保留该能力，启用与否不影响测算成立**。

## 为什么不是别的做法

| 备选 | 否决理由 |
|---|---|
| 全部删掉（连台账一起） | 台账在**复核**（这数哪来的）与**责任划分**时有用。删掉是丢能力，不是减复杂度 |
| 保留关卡但把措辞写委婉 | 措辞不改变「算不了」的事实；用户仍会被拦住 |
| 把缺口记成「默认值」以求放行 | **违反 ADR-0004**。降级为 INFO ≠ 允许编值：值必须保持**完全缺失** |
| 只降级附证、保留来源 BLOCKED | 来源同样不参与算式，按准则一视同仁 |

## 与既有规则的关系

- **ADR-0004 仍然成立且被强化**：不阻塞 ≠ 可以填默认值。值必须完全缺失
  （已加测试 `test_not_declared_is_not_silently_defaulted` 锁定）。
- **ADR-0007 仍然成立**：Agent 不得代为落值——这条与「阻不阻塞」无关。
- **ADR-0011 仍有用**：交叉满足减少了重复索取，方向与本次一致（都是减少无谓摩擦）。

## 后果

- 现状：`cost-check` PASS 7 / INFO 1 / WARN 1；`qty-check` PASS 4 / INFO 1 / SKIP 1 / WARN 1
  ——**两侧均无阻断项**，测算可以开始。
- 代价：将来若出现「不知道成本哪来的」而结论又被质疑的情形，没有关卡会提前拦；
  这是有意的取舍——**把判断权交还给使用者，而不是替他设卡**。

## 教训（写给未来的自己）

同一类质询已出现四次，根因是同一个**系统性倾向**：
**把「可追溯性」与「正确性」混为一谈，用同一套阻塞机制同时管两件事。**

治理要区分三档，不可混用：

1. **正确性**（算得出、算得对）→ BLOCKED
2. **可解释性**（说得清、方向正）→ WARN
3. **可追溯性**（查得到出处）→ **INFO**
