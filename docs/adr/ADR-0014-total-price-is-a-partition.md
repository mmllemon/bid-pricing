# ADR-0014：总价是一个「划分」—— 甲供材料费只减计税基数

- 状态：**已接受**（2026-09-17）
- 关联：ADR-0002（机制 vs 数据）、ADR-0005（闭合 ≠ 完整）、ADR-0007（沉默不是断言）、
  ADR-0013（台账不是关卡）、T00-06B 实施路线 §任务表原式

---

## 背景

T00-06B 要求在 C1 总价锁定之前，把「可竞争部分到底有多少钱」算清楚。路线
v3.2.1 原文给了两式：

```
① P_competitive(p) = P*(p) − Σ_{i∉X_opt} p_i q_i^0 − Σ(暂列金额) − Σ(甲供材)
② P*(p) = P_competitive(p) + f(p) + 暂列金额 + 甲供材 + Tax(p)
```

路线自己警告过：「**该简化式会与 ① 的扣减项重复或漏计，C1 总价锁定偏差可达
数千至数万元**」。但警告只说「不要省略」，没说**省略掉的那一项该怎么算**。

按字面实现 ①② 会出现两个自相矛盾：

1. **甲供材料费同时是减项（①）与加项（②）**；
2. **暂列金额既在「Σ_{i∉X_opt}」里被减掉，又作为独立加项被加回**——因为
   暂列金额本就是其他项目清单里的一行，属于 `i ∉ X_opt`。

## 裁定依据：不是推理，是两份现存证据

**证据一：实测恒等式**（真实样本 tag `real-sample-identity-v1`，残差 0）

```
总价 = 分部分项工程费 + 措施项目费 + 其他项目费 + 规费 + 税金
```

四个税前项 + 税金，**没有甲供材料费这一项**。

**证据二：招标文件表-12 的原文**（`fee_and_tax[*].basis` 字段，逐字引用）

```
增值税  计税基数 = 分部分项工程费+措施项目费+其他项目费+规费-甲供材料费   税率 9%
附加税  计税基数 = 增值税                                            税率 12%
```

即 **甲供材料费出现在计税基数里，不出现在总价里**。这两份证据合起来唯一地
确定了正解，不需要任何主观判断：

```
P*          = P_COMPETITIVE + P_FIXED_PRETAX + TAX          （划分，三桶）
计税基数     = 分部分项 + 措施 + 其他 + 规费 − 甲供材料费        （表-12 原文）
```

`Σ_{i∉X_opt} p_i q_i^0` 就是 `P_FIXED_PRETAX`（暂列金额是它的内部一笔），
而 `TAX` 不是扣减项而是**派生项**——它依赖报价水平，但这个依赖是可解的：

```
k = r_增值税 × (1 + r_附加税)
C = (P* + S·k) / (1 + k) − A        S = 甲供材料费，A = 固定税前部分
```

## 决策

### 1. 总价是划分，不是加加减减的清单

每个金额**必须落在且仅落在一个桶**里：`COMPETITIVE` / `FIXED_PRETAX` / `TAX`。
甲供材料费**不是桶**，是计税基数的一个减项——它在数据结构上与桶平级但语义不同
（判据 TP-02 专查它有没有被写成加项）。

### 2. 「其中：暂列金额」是父项的披露列，不是独立加项

原式之所以会重复计，是因为把「其中」当成了「另有」。做法上的修正是**结构性的**：
`Term.disclosure` 是父项金额内部的子字段，因此「暂列金额既在父项里又被单独
加一次」这个错误**在数据结构上表达不出来**，不依赖人记得别加两次。

判据 TP-02 另有算术兜底：披露额不得大于父项金额。

### 3. 计税基数以招标文件原文为准，不得由实现自行决定

判据 TP-07 把该段原文当输入：去空白后必须匹配「四个加项 + 一个甲供材减项」。
文件怎么写就怎么算；换个文件说了别的，判据立刻失败并在实现侧强制修改。
**这正是「机制 vs 数据」（ADR-0002）在本项的具体落法**：公式结构是机制，
正文是数据。

### 4. 舍入：分项先舍、汇总再舍一次；附加税以**舍入后**的增值税为基数

并新增全仓统一的金额舍入入口（[ADR-0016](ADR-0016-money-rounding-half-up.md)）。

### 5. 联动函数 `compute_P_competitive` 的入参不是报价向量

路线原文写作 `compute_P_competitive(p)`。**以 `p` 为入参会把 C1 变成恒真式**：
左端 `Σ_{i∈X_opt} p_i q_i^0` 与右端由同一个 `p` 算出，任何报价都「满足」C1。
故入参取**锁定的总价**，出参才是 C1 右端，并由判据 TP-05 做往返校验
（反解 → 正算必须回到同一个总价）。

## 影响

* 新增 `src/bidpricing/total_price.py`（T00-06B 的可执行规范）+ 判据 TP-01～TP-07；
* 新增 CLI `total-price-check`，在真实样本上：三桶 1,264,184.26 / 22,381.74 /
  129,685.85，合计 1,416,251.85 与源工作簿一致；
* 限价侧表-04「分部分项工程费」为空时**拒绝装配**而不是补零（ADR-0005 实证）；
* 五组报价（控制价 / ±10% / ±20%）逐组手工复算，最大偏差 0.00 元；
* 合成算例证明：把甲供材漏掉会让反解出的可竞争部分偏小（差值 ≫ 0.01 元容差），
  即**判据可被错误的值否定**。

## 遗留

* 真实样本的暂列金额与甲供材料费均为 0，故「重复计」「漏甲供材」两类错误在本
  项目数据上**数值不可观测**——这两点的区分力只能由合成算例承担（已建）。
  一旦真实项目出现非零暂列/甲供，须补一组真实数据回归。
* 表-04 未拆分「施工技术措施 / 施工组织措施」，故当前把措施项目费整体置于
  `FIXED_PRETAX` 并显式登记该限制；T00-06 项目落值表就位后才能分离，
  届时 `COMPETITIVE` 会变小、`FIXED_PRETAX` 会变大，但**总和不变**。
