# ADR-0015：利润口径必须指名道姓 —— 目标函数唯一，且判据不得自证

- 状态：**已接受**（2026-09-17）
- 关联：ADR-0004（未定态）、ADR-0009（整体利润口径）、ADR-0011（交叉满足）、
  ADR-0014（总价划分律）、T00-12

---

## 背景

T00-12《利润口径桥接表》要解决路线写明的一个失效模式：

> 「必须明确 Price→DirectCost→Management→Profit→Fee→Tax **哪一层级进入优化**，
> 否则会出现**『算的是税前利润、报告写的是含税利润』**。」

这句话的危险在于：它不是算错，而是**两个都对的口径被混用**。项目越大，
两个口径的差额（税金 + 不可竞争费）越大，而报表上只有一个数字。

## 决策

### 1. 「参与目标函数」与「目标函数本身」是两件事

第一版实现把两者混成一个字段 `enters_objective`，于是「收入参与目标、成本参与
目标、目标本身是利润」被判成「有三个目标」——**判据自己抓到了这个混淆**。
拆成两件事：

| 字段 | 含义 | 约束 |
|---|---|---|
| `enters_objective` | 是否参与目标函数的定义（含目标本身） | 必须**显式等于** `{objective.level} ∪ objective.operands`，不多不少 |
| `is_objective` | 本行就是被最大化的那个量 | 恰好一行；且 `kind=OBJECTIVE` 的行必须为真 |

「多标」会把外生常量（税金）误当决策项，「少标」会把决策项漏出目标，
两个方向都由同一判据覆盖。

### 2. 差额项必须显式列出，且必须指向已声明层级

`reported_vs_objective.difference_terms` 列出目标口径与报告口径之间的差额来源
（本项目：`TAX`、`NON_COMPETITIVE_FEES`）。为空 → FAIL；引用了不存在的层级
→ FAIL。**不允许「差额构成」写成一句形容词**。

### 3. 常数项不进目标函数，但必须在报告层出现——这是结论，不是省略

税金依赖报价水平，但**不依赖分配**：总价锁定下，怎么在 `X_opt` 内部分配，
税金都一样。故它在「预算固定下的分配问题」里是常数，**常数不影响最优解**。
判据 TP-06 用五组报价把这一点钉死（税金在 ±20% 报价下必须变化，证明它没有
被当成固定值搬进总价）。

### 4. 单项亏损：目标只约束总利润

落值为 `TOTAL_PROFIT_ONLY`，依据用户 2026-09-16 裁定原话：

> 「考虑整体利润，本来单项清单就是有亏有赚的」

实现见 ADR-0009（C4 地板被招标上界钳制，亏损项由 C6 总量约束兜底）。
故**禁止**把「逐项均不亏损」当作求解目标或后置过滤——那会切掉最优解。

### 5. 判据不得自证（本节是本 ADR 最可复用的部分）

PB-03 的第一版实现是这样的：

```python
b1 = abs(partition.total − (partition.pre_tax + partition.tax))   # 恒等于 0
b2 = abs((Σ COMPETITIVE + Σ FIXED_PRETAX) − partition.pre_tax)    # 恒等于 0
```

两边都由同一个派生量算出，**恒为 0，永远 PASS**。是测试里刻意构造的
「多出一行税金」的划分把它抓出来的——判据写成了恒真式，等于没有判据。

修正后的对账必须**跨来源**：

| 判据 | 左 | 右 | 为什么不同源 |
|---|---|---|---|
| n1 | 三桶之和（来自明细行） | **外部给定**的总价 | 一侧是明细，一侧是表列/给定值 |
| n2 | 声明的税金行 | 由计税基数**派生**的税金 | 防「两处各算一遍」 |

**通用判据**：一个判据若两侧可以同时由第三个数推出，它就不是判据。
本项目此前在别处也踩过同类（ADR-0005「闭合 ≠ 完整」：恒等式闭合只证已声明
分项自洽）。**凡「同源相减」形式的校验，都要问一句：这两个数会不会同时错？**

## 影响

* 新增 `config/profit_bridge_spec.json`（Gate 0b 受控制品，已冻结
  `sha256:5d42943755f3`）+ `src/bidpricing/validation/profit_bridge.py`（PB-01～PB-06）
  + CLI `profit-check`；
* 目标口径 `Z_OBJECTIVE = R_SETTLEMENT − C_SETTLEMENT`，税口径 `EXCL_VAT`，
  与 `basis_declarations` 两侧一致（机制层已定，**不重复索取声明**——ADR-0011）；
* 「未给划分」时 PB-03 记 **SKIP 而非 PASS**：没检查不能被读成检查过；
* `frozen_by` 如实记为 `agent(代操作…)`——业务声明与机制冻结的责任归属不同，
  不得用同一个字段冒充（ADR-0007）。

## 遗留

* `R_i` 的最终形式取决于 T03-01 结算规则引擎与计价规则卡 P1 三分支；本表只固定
  「用 q¹ 算收入、q¹ 算成本、税前口径」三条，不重复定义分支规则。
* 报告口径是否再扣企业层面分摊（`cost_basis_spec.allocated_overhead`）由 T06-03 决定。
