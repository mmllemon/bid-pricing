# ADR-0020：等式容差取模式 A（内部严格等式 + 输出层独立舍入调和）

- 状态：已采纳（2026-09-17）
- 任务：T00-04（完成判据 = `equality_tolerance_mode.current` 非 null）
- 制品：`config/precision_profile.json`（冻结后 `sha256:146e8e6ffbc4`）
- 相关：实施路线 v3.2.1 §8.2；ADR-0019（同批治「证明与实现同源」的同类问题）
- 授权：用户 2026-09-17「自主裁定，继续推进」

## 背景

实施路线 §8.2 把「等式约束容差化」立为**二选一、不得混用**：

| 模式 | 形式 |
|---|---|
| A | 内部严格等式 + 仅对最终输出做舍入调和 |
| B | 全程容差带 `|.| ≤ ε_P`（此时 Phase 3 复核必须使用同一 `ε_P`） |

该制品的 `current` 长期为 `null` —— 而它是 T00-04 的完成判据，T00-04 又是
T04-02A（LP 形式化）的硬前置。也就是说：**LP 建模从哪一步开始就卡在这个未定态上**。

同时 §8.2 末段留了一句：「『等式约束性能显著更差』不应写成无条件事实，**须在本
项目 benchmark 后决定**」。这句话很容易被当成「所以先不决定」——但 benchmark 不在
关键路径上，而 T04-02A 在。未定态必须消解。

## 决策

### 一、取模式 A

`equality_tolerance_mode.current = "A"`。

### 二、模式 B 被一条**与 benchmark 无关**的判据否决（D1）

这是本次裁定的核心，也是它不能靠 benchmark 翻案的原因：

> **外层复核必须能独立否定内层解。** 模式 B 把内层残差判据与外层复核判据设成
> **同一宽度** `ε_P`，于是「残差恰好落在带内」的解同时通过两关——复核层退化成
> 内层判据的**复制**，丧失独立否定能力。

机械判据：两层判据宽度之比 `R2 = outer_tol / inner_tol`，要求 `R2 ≥ 1e3`。

| 模式 | outer_tol | inner_tol | R2 | 判定 |
|---|---|---|---|---|
| A | `eps_abs` = 0.01 元（舍入分辨率） | `eps_solver` = 1e-8 | 1e6 | **PASS** |
| B | `ε_P` | `ε_P` | 1 | **FAIL** |

这条与项目里已有的通用判据同源：**一个判据不得能被两类不同性质的失败通过**。
此处是它的反向形式——**判据不得是另一个判据的复制，否则等于没复核**。

`on_violation = FAIL`，且**不可用 benchmark 翻案**：性能问题必须在保住 D1 的前提下
另解（见 `reopen_condition`）。

### 三、模式 B 在本项目量级上也无收益（D2）

容差带要起「放宽」作用，必须显著宽于求解器默认的原始可行性容差：

```
R1 = eps_solver / HiGHS.primal_feasibility_tolerance = 1e-8 / 1e-7 = 0.1 < 1  ⇒ FAIL
```

`ε` 是按 §5.3 取的**绝对**残差 1e-8，而被约束量 `Σ p_i q_i^0 = P*_competitive` 的量级
是 1e6 元 —— 折合相对量 **1e-14**，已经紧到接近 double 在该量级上的表示粒度
（`ulp(1e6) ≈ 2.3e-10`，带半宽仅约 43 ULP）。这样的带：

- 宽不到 HiGHS 默认容差的 1/10 ⇒ **不可能放宽求解难度**；
- 远小于报价分辨率 0.01 元 ⇒ **也不可能吸收舍入**（吸收舍入是 T06-06 的职责）。

**推论（很重要）**：D2 同时否定了「改 A 会更难解」这一顾虑。模式 A 的实现同样是
把求解器容差收到同一量级（`primal_feasibility_tolerance = 1e-9`），**两者求解难度等价**。
所以这个二选一里，B 付出的语义代价换不到任何东西。

### 四、模式 A 的实现边界（内层 / 外层各一套判据）

| 层 | 形式 | 判据 | owner |
|---|---|---|---|
| 内层（求解） | `Σ_{i∈X_opt} p_i q_i^0 = P*_competitive`（严格等式）+ `primal_feasibility_tolerance = 1e-9` | `eps_solver` = 1e-8（原始可行性残差） | T04-02B/C |
| 外层（交付） | 四舍五入 → 总价重算 → 差额修正 → 全约束复验 | `eps_abs` = 0.01 元（舍入分辨率） | **T06-06** |

求解器容差 1e-9 在报告里必须声明为**数值极限**而非语义容差 —— 它不授权解偏离
`P*_competitive`，只授权浮点舍入。禁止把「求解器内已容差化」当复核依据（§8.2 原话）；
禁止用 `eps_total` 做舍入后校验（它是**残差**容差，不是**舍入**容差）。

### 五、§8.2 的「两层同一 ε 口径」不构成对 A 的违反

该条禁的是**松进严出**（内层容差化、外层严格等式）——那会误杀求解器只能给出带内
残差的可行解。其正确实现是「**内层放宽的部分必须在外层被显式补偿**」。模式 A 使
内层**无放宽** ⇒ 无需补偿 ⇒ 两层口径天然一致（都是「不许偏离 `P*_competitive`」）。

模式 B 是「两层同宽」的**字面**读法，代价是 D1。故 **A 是该条的更强满足，不是违反**。
这条读法已写入制品 `clause_8_2_reading`，以免日后有人拿字面措辞推翻本裁定。

## 重开条款（把「未 benchmark」变成显式状态，而不是隐式假设）

`benchmark_status = "NOT_RUN"`，重开需**同时**满足：

1. `benchmark_status = RUN_FAIL`，且
2. `R1 > 10`（容差带确实宽于求解器默认容差一个数量级以上），
3. 测法：同一实例集（须含真实样本 `xiyong_l_district` 电气设备安装工程）上，
   严格等式式 vs 不等式带式的 **P95 求解时延之比 > 1.5**，且实例规模 `n ≥ 1e4` 项。

**且 D1 不可交易**：即使重开，也只能改内层表示（严格等式 → 不等式带 + 外层显式补偿项），
**外层必须始终是独立严格判据**。禁止把外层一并放宽。owner = T04-06。

不设该条款的后果是：「没有 benchmark」这件事会以「§8.2 说过要 benchmark」的形式
永久悬在制品里，而每一个下游任务都得重新推一遍「它到底定了没」。

## 遗留

- `benchmark_status = NOT_RUN` 属**已知未做**，非阻塞项；owner = T04-06。它被显式
  记录而非隐式假设，故下游任务无须重新推演。
- 本裁定只覆盖 C1。C6/C9/C10 的**总价类**残差仍用 `eps_total`，与 C1 的内层判据
  `eps_solver` 不同名不同宽 —— 这是有意的：`eps_solver` 约束的是求解器**原始可行性**，
  `eps_total` 约束的是**业务量级的总价一致性**。二者不得互相替代。
