# ADR-0021：LP 形式化 —— 目标线性性是 LP 成立的唯一依据；三条约束须改变位置

- 状态：已采纳（2026-09-17）｜ **决策一已被 ADR-0022 推翻**（superseded-in-part：见下「后续修正」）
- 任务：T04-02A
- 制品：`config/lp_formulation_spec.json`
- 实现：`src/bidpricing/solver/formulation.py`、`cli formulate-check`
- 相关：实施路线 v3.2.1 §8.1/§8.2、T04-02A；model_v0.3_R2.md §5.4/§7.1
- 前置：ADR-0020（等式容差模式 A）—— 本任务依赖它解封（T00-04 完成判据）

## 背景

T04-02A 的判据是「变量、目标、约束映射完整；总价约束按可竞争部分实现；
C1 按容差带实现」。真做下去才发现，这条判据的**实质内容**不在「把 C1–C13
写全」，而在于三件事：

1. 目标到底是不是线性的（决定 LP 是否成立）；
2. 哪几条看起来像约束的东西其实**不是**决策约束；
3. 「按可竞争部分实现 C1」之后，右端 `P*_competitive` 由谁提供、作用域是什么。

这三件事里的任何一件搞错，形式化都能「写全」但仍然全错。

## 决策

### 一、目标对 p 严格线性 —— 这是 LP 成立的唯一依据

```
Z = Σ_{i∈X_opt} q1_i · ( r_eff_i · p_i − c_i )
∂Z/∂p_i = q1_i · r_eff_i
```

`r_eff_i` 由 `(r_i = q1_i/q0_i, 规则集参数, alpha_i)` 决定 —— **全部是外生给定**。
所以 P1 的哪个分支在**建模期**就已知，`settlement_revenue` 对 p 是线性函数。

推论（本次最重要的结论）：

- **LP 成立**，不需要为 P1 的分段引入二元变量；
- **MILP 的唯一来源是 C7 的二元变量** `z_i` —— 这正是 F-09 判据「MILP 切换条件唯一」的依据；
- C9（`Z ≥ Z_min`）也因之是线性的。若目标是非线性的，C9 会连带变成非线性约束。

容易搞混的是两个边际：`∂R_i/∂p_i = q0_i · r_eff_i`（收入对报价，这正是
`r_eff` 的定义式）与 `∂Z/∂p_i = q1_i · r_eff_i`（目标对报价）。二者相差 `r_i` 倍。
**F-02 检前者**，目标系数由前者乘 `r_i` 导出，不得各自实现一份。

> ⚠ **后续修正（2026-09-19，superseded-in-part）**：`∂Z/∂p_i = q1_i · r_eff_i`
> 一句**已被 ADR-0022 决策三推翻**。正确形式是 `∂Z/∂p_i = q0_i · r_eff_i`
> （即目标对 p 的边际等于收入对 p 的边际；目标不含 p 的项 `c_i·q1_i` 与 p 无关）。
> 原写法把排序键 `(目标系数)/(C1 系数)` 又乘了一遍 `r_i`，导致解满足全部约束但次优。
> 见 [`ADR-0022`](ADR-0022-lp-compiler-positions.md) 决策三。
> 本 ADR 决策一的**结论**（LP 成立、MILP 唯一来源是 C7 的 `z_i`）仍然成立；
> 被推翻的仅是**边际表达式**，不是 LP 的线性性结论。

### 二、C5 的 LP 下界必须抬到报价分辨率

schema 写的是 `p_i ≥ eps_price`，而 `eps_price` 是**相对量**（×P*）。
P* = 1e6 时它只有 **1e-3 元** —— 舍入到 0.01 元后变成 **0.00**，即
**实际提交的报价违反 C5**。

故 LP 下界取 `lb_C5 = max(eps_price·P*, rounding.resolution)`。

这是内层约束与外层舍入的**耦合点**，正是 ADR-0020 选模式 A 时要显式处理的对象：
模式 A 的两个层不是同宽的，所以「内层允许 1.4e-3 的报价」这件事**不会**在外层
被自动纠正 —— 它会被舍入成零，然后外层判「报价为零」而整份报价作废。

判据 F-06 的设计有一处坑：若把期望值在手边重算一遍，判据退化成恒真式
（`max(a,b) ≥ b` 永远成立）。故必须在 `eps_price·P* < resolution` 的区间上取点
（探针 P* ∈ {1e3, 1e6, 1e9}），且比较的是**实现报出的 `lb_c5`**。

### 三、C12 退化为「约束面上的常量」—— 前置体检，不是 LP 约束

`R_pc = Σ p_i q0_i / Σ c_i q0_i`。在满足 C1 的**可行域上**，分子是常量：

- 若 Σ 遍历 `X_opt` ⇒ 分子 = `P*_competitive`（C1 直接给出）；
- 若 Σ 遍历全部项 ⇒ 分子 = `P*_competitive` + `Σ_{非 X_opt} p_i q0_i`，
  而后者是外生给定单价 ⇒ 仍是常量。

两种作用域读法给出**同一结论**。所以写成 LP 约束只会得到一条在可行域上
**恒真或恒假**的平凡约束：不约束解、不产生松弛量、也不参与诊断。更糟的是
它会掩盖真实问题 —— 若 `R_pc < R_min`，该做的是判「这个 P* 不可接受」，
而不是让求解器报 infeasible。

**精确性要求**：恒定性是**约束面上的性质**，不是函数意义上的常数。
作为无约束函数 `∂R_pc/∂p_i = q0_i / Σc q0_i ≠ 0`。判据 F-08 必须用
「**两组不同的 p 向量**（都满足 C1）给出同一 `R_pc`」来检，**不得**用偏导为零。
用函数判据会得到假 FAIL；而把「两组解」写成 `B/den` 两次则是同一个数的复制，
同样是恒真式。

### 四、C11 挂账，不替 T04-02B 决定语义替换方向

schema 的 metric 是「MAD 或 σ」——两个候选都有代价：

- `σ` 需二次/二阶锥约束 → 把问题推离线性，Phase 1 解析解不再可比；
- `MAD` 需辅助变量 `u_i ≥ |d_i − 中心|`，而「中心」（d 的均值）**本身依赖 p**
  ⇒ 引入自由度，中心被优化选择时约束会**变松**。

两者是**方向相反**的语义替换（σ→MAD 收紧、MAD-with-free-center 放松）。
在形式化阶段静默选定任一个，都会让「制品说什么」与「实现做什么」脱钩。
故本任务只挂账 + 给出约束：选定者必须在制品里声明差异方向与证明，且若招标文件
明确以**标准差**表述上限，则任何替换都不成立，须退回判定层。

C11 是 P1 且可开关，故其形式未定**不阻塞** P0 主干。

### 五、判据的覆盖面不得取决于被测数据

F-02 必须**自己扫** `adjustment_scope ∈ {FULL, SEGMENT}`，不得沿用实例的 scope。
理由来自首跑踩到的坑的另一面：本项目实例恰好是 SEGMENT（分叉所在处），看起来
「撞上了」；但只要实例改回 FULL，这条判据就再也测不到那个分叉。
**判据的覆盖范围不能由被测数据决定。**

## 本次抓到的两个 bug

### bug 1（实现）：`settlement_revenue` 的区间内分支漏了作用域判断

`SEGMENT ∧ 区间内 ∧ alpha≠0` 时，`settlement_revenue` 返回含 `(1+alpha)` 的收入，
而 `compute_r_eff` 返回 `r`（不含 alpha）—— 两者相差 `(1+alpha)` 倍。

根因：`compute_r_eff` 的区间内分支区分了作用域（FULL → `(1+α)r`，SEGMENT → `r`），
而 `settlement_revenue` 的 else 分支直接 `q1*p*(1+alpha)`。按 §5.3.1（alpha 只作用于
FULL），**后者是错的**。已修。

为何此前不可见：本项目 `alpha = 0`，分叉被完全掩盖。一旦 alpha 设非 0，
解析解与 LP 解就会不一致，且**不触发任何可行性检查** —— 与 T04-00 抓到的
SEGMENT 分支 bug 属同一类：**自洽的错公式仍然自洽**。

### bug 2（判据本身）：F-02 首版借道 `instance.r_eff`，两侧用了不同作用域

首版实现里解析式走 `instance.r_eff(item, scoped)`，但该函数内部会回到实例自己的
`Phase1Params`，把传入的 scope 覆盖掉 → 解析侧恒用 SEGMENT、差分侧用传入 scope
⇒ 判据**自己制造出假 FAIL**。

修法：解析式直接用 `compute_r_eff(r_i, scoped, alpha)`，两侧严格同参数。

这条值得单独记录，因为它展示了判据编写的一个反向风险：**判据太紧会误杀正确实现**。
「能被错误的值否定」与「不能被正确的值否定」是同一条要求的两个方向，后者常被忽略。
