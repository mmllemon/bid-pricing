## 背景

T04-00 证明了「阈值分割结构在 A 组条件下与 P_A 最优解一致」，但**证明不等于解**：
仓库里此前没有任何代码把那个结构变成一组 `p_i`。缺它有两个后果：

1. **T04-04 对拍只剩一方。** 对拍的价值建立在「两条独立路径」之上；只有 LP 一侧
   时，「两路径一致」无从谈起，T04-08 的三层隔离也没有第一层。
2. **λ 与层归属无处产出。** 这两个量不是 LP 的输出形态——它们是**结构解释**，
   只有解析算法才知道「谁顶格、谁触底、门槛在哪」。

同时 T04-00 给了一个很窄的票据：`check_exactness` 判 `EXACT` 才算「在适用子集
内」。T04-01 的全部设计难点都集中在一句话上：**这个票据要怎么用**。

## 决策

### 一、适用子集守卫放在**求解之前**，越界给解判 BLOCKED

`impl_plan_v321 §4.1` 说得很清楚：「一致性只在适用子集内要求」。这句话有一个
容易走反的推论——**在子集之外给一个解，比不给解更危险**：

T04-04 会把这个解与 Phase 2 的解比对，判出「不一致」；而 T04-04 的报告规则
（v3.2.1 P2-⑩）要求对拍结论只能建立在一致性之上。于是**正确行为（不一致）
被读成了缺陷**，真正的 bug 被噪声淹没。

因此本层的第一个动作不是构造变量，而是：

```
check_exactness → EXACT ？ 否 ⇒ BLOCKED，逐条点名被否定的 A 组条件
                        是 ⇒ 继续
```

`PS-01` 是这个守卫的机械判据，且**两个方向都测**：EC-5 判 FAIL 的实例必须
BLOCKED（拒绝给解）；同一实例声明 canonical tie-break 后必须给解。

### 二、排序键是 **r_eff**；次键写死为 item_id 升序，未支持的策略判 BLOCKED

T04-00 的 EC-2 已经量化了「按 `r` 排序会给出满足全部约束但**次优**的解」。
本层把这条约束落到实现上，并把**次键**（tie-break）也写死：

- platform（多个项 `r_eff` 相同且可容纳总价分配）下，不同的次序给出**不同的
  最优解**，而 §4.1 的三级变量一致性判定要求一个确定的代表元。
- 本项目支持的策略只有 `CANONICAL_ITEM_ID`（`item_id` 升序）；
- 实例声明了**其它**策略 ⇒ `BLOCKED`，**不得**静默改用它没声明过的次序——
  那等于替被复核对象选了一个解（never_downgrade，与 ADR-0023 的
  `UNSUPPORTED` 同一条纪律）。

★ 一个必须说清的事实：**在 `r` 与 `r_eff` 同序的实例上，PS-04/PS-05 没有区分力**。
本层因此专门构造了逆序实例（`ρ⁻ = 0.5` 使 `r = 0.84` 的项 `r_eff = 1.26`，
高于 `r = 0.90` 而 `r_eff = 0.90` 的项）作为 PS-04 的见证：**判据的覆盖面
不得取决于被测数据**（Skill §4 的同一条）。

### 三、不限价项（`cap` 空）交给前缀和的 `+inf`，**不特判、不折 0、不用大 M**

EC-9 留了一条实现性义务：「实现须把不限价项固定为临界项显式求解」。
本层的做法不是加一个 `if ub is None` 分支，而是让 **前缀和自然产出该结论**：

若 `i_m` 是排序后首个不限价项，则 `S(m) = +∞ > B`，故必有 `k* ≤ m−1`；
于是前 `k*` 项的上界必然有限，不限价项**只可能是临界项或触底项**。

三种错法各自的后果都被判据钉住（`PS-07`）：

| 错法 | 后果 | 判据 |
|---|---|---|
| 折成 0 | `p = 0` 与 C5「单项报价不得为零」冲突，可行解变不可行 | `PS-03`（`p ≤ 0`）+ `PS-07` |
| 折成 1e9 之类的大 M | `B` 较大时该项被「推满」，解不再是 P_A 的解 | `PS-07`（超出 C1 隐式上界） |
| 因存在不限价项而拒收 | cap 空是**合法语义** `ALLOW_EMPTY_NO_CAP`，不是数据缺口 | `PS-01`（EC-9 判 WARN 不阻断） |

这与 DQ-03/DQ-05 的「空 cap ≠ 0」是同一族错误第三次出现，故本条单列为决策
而非实现细节。

### 四、目标值只由独立裁判给出；判据只吃「实例 + 解向量 + 制品声明」

`Phase1Solution` **刻意不含 Z 字段**（`PS-10` 机械断言）。理由：

- 本层再算一遍 `R_i` 就是自造第二个事实源——而 `R_i` 与 `r_eff` 的唯一实现
  在 `contracts/pricing_card`（ADR-0015）。
- 目标值交给 `instance.check_solution`：它只做「代回原式」，不复用求解路径。

`judge_phase1` 的入参只有「实例 + 解对象 + 制品声明的输入集」。于是**坏解可以
被直接注入**——测试里把解换成篡改过的对象，对应判据必须翻成 FAIL。做不到
这一点的判据，在测试里只能证明「我的实现恰好是对的」。

### 五、`_merged_lower` 提升为公开名 `merged_lower`

解析解与 LP **必须是同一个箱型**。此前合并逻辑是 `formulation` 的私有函数，
解析解若自行取一遍 `max(L, floor, lb_C5)`，就产生第二处口径——两侧差一点点，
T04-04 的「不一致」将无法归因。

同理，`cli` 里 `floor_i` 的来源解析（显式文件 / T03-02 派生量层 / 都没有）
抽成 `_resolve_floor_by_id`，由 `verify-solution` 与 `phase1-solve` 共用：
「同一约束两侧各写一遍」正是本仓反覆出现的根因（规则⑨）。

### 六、★ 实测照出一处**既有判据的缺口**：EC-7 的可行性证书用错了下界

`_ec7` 的边界证书用 `item.L` 求和得 `P_min`；而 P_A 的真实下界是
`merged_lower = max(L_i, floor_i, lb_C5)`。当 `floor_i > L_i`（μ 落值后必然发生）
或 `lb_C5 > L_i` 时：

> `P_min^{EC-7} < P_min^{P_A}` ⇒ **EC-7 可以判 PASS，而 P_A 已经空了。**

本层因此以 `INFEASIBLE`（不是 `BLOCKED`）兜住这一格，并在测试里用
`floor_by_id={"F1": 400.0}` 复现（`L = 100`、`q0 = 1000`、`B = 2×10⁵`
⇒ EC-7 看 `1×10⁵ ≤ B` 判 PASS，真实下界 `4×10⁵ > B` 判 INFEASIBLE）。

**但本层不改 EC-7。**「改闸门判据集 = 改已批准的方案」，须先与用户确认
（Skill §2）。记入遗留 ①。

★ 顺带记一条**反向**教训：`INFEASIBLE` 与 `BLOCKED` 必须分域。前者是
「算出来了，可行域为空」，后者是「算不出」。混同会让「B 定得太低」（业务问题）
以「数据没齐」（数据问题）的样子长期留档（Skill §命名与编号的同一条）。

## 影响

- **T04-04 有了第一方。** 对拍的双方现在是「解析（本层）+ LP/MILP」，且本层
  的守卫与 T04-00 的 verdict 严格一致，可比性由构造保证。
- **T04-01 遗留 1 闭合。** ADR-0019 的遗留 1 说「`§7.1.1-5` 时序断言目前空真
  通过（尚未有 WP4 Phase 1 构建记录）」——本层落地后该断言已有对象可判。
- **`phase1-solve` 的退出码**：verdict = PASS 时 0，否则 1。在内置探针上恒
  0（两条探针都在适用子集内），在 `--instance` 给不可适用实例时恒 1——后者是
  **如实反映**，故本命令与 `verify-solution` / `derive-check` 一样，其
  `--instance` 分支**不进常驻验证环**。
- **`PS-06` 首版太松，被自己的用例照出。** 数值交换见证原本只扫 `i < j` 的
  下标对，而交换是**定向**的（i 下调、j 上调）——「让高 `r_eff` 项上调、
  低 `r_eff` 项下调」这一半方向被漏掉，而它恰是次优解的常见形态。造出的
  「可行但次优」用例因此被判 PASS。修法是遍历**有序**对。这条与 ADR-0024 的
  SV-03 属同一类：**判据太松与判据太紧都会静默失效**，只有注入式反例能照出来。
- 测试数 790 → **838**（新增 48）。

## 遗留

1. **EC-7 的 `P_min` 应改用 `merged_lower`**（决策六）。这是 T04-00 的一处
   实质缺口：当前口径下「B 低于真实下界」会被 EC-7 放过，直到本层的
   INFEASIBLE 分支才被兜住。修它 = 改 `phase1_exactness_spec` 的判据集，
   **须先与用户确认**。
2. **`phase1_solver_spec` 未登记进任何闸门注册表。** 与 `phase1_exactness_spec`
   同状态（Gate 3 注册表尚未建立）。是否新建 Gate 3 属改动闸门判据集，待裁定。
3. **真实项目入口未开。** 跑本层需要 `B`、`c_i`、`q0/q1_point` 的逐项落值，
   而当前 master 表只有 `cap` 与成本单价（q1 的 `attribution`/`point` 未落值，
   与 T04-00 遗留 4 同因）。故 CLI 默认跑内置探针；真实实例待 T04-04 的
   `golden_dataset_v1`。
4. **`floor_i` 在本项目上仍恒为「未产出」**（μ 未落值，OI-DQ-A）。本层与 LP
   在此保持一致地「都不含地板」；μ 一旦落值，两侧必须**同时**取到，否则对拍
   出现假不一致。T04-04 的报告须声明 floor 来源。
5. **数值稳定化未做。** 本层不截断、不归一、不消解 platform——EC-8 的舍入义务
   随 `notes` 透传，由 T04-06 / T06-06 承担（与 EC-8 的 owner 一致）。
6. **`INFEASIBLE` 的上界侧分支（`B > P_max`）当前不可达**：EC-7 用的是同一份
   `U`，会先判 FAIL。留作防御性兜底，不是主路径（测试中已具名说明）。
