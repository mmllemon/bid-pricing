# 真实样本溯源说明 —— 西永L分区配电工程（限价 / 报价配对）

## 一、这是什么

本项目第一份**真实的、同一项目的「招标限价 + 投标报价」配对数据**。

| 项 | 内容 |
|---|---|
| 工程名称 | 西永L分区公立学校（暂定名）一期工程等项目配电工程 |
| 单位工程 | 电气设备安装工程（单标段、单单位工程） |
| 限价文件 | `真实案件示例/中标限价/西永L分区公立学校（暂定名）一期工程等项目配电工程.xlsx` |
| 报价文件 | `真实案件示例/报价/西永L分区公立学校（暂定名）一期工程等项目配电工程.xlsx` |
| 提取日期 | 2026-09-16 |
| 制品 | `pair.json`（本目录） |

两文件结构完全一致，各 6 张子表：

```
000001  表-04 单位工程投标报价汇总表
000002  表-09 分部分项工程项目清单计价表        ← 主体，81 条明细
000003  表-09 施工技术措施项目清单计价表
000004  表-10 施工组织措施项目清单计价表        ← 费率式
```

## 二、为什么这份样本重要

1. **逐项可比**。两文件的 81 条明细编码集合**完全相同**（无差集），因此每一条都能
   配成一对 ``(p_cap, p_bid)``。示例模板做不到这一点——那四份分属不同项目。
2. **恒等式精确闭合**。报价侧残差为 **0.0000**（见下）。于是恒等式第一次有了
   真实样本背书，而不是只在文档里写着。
3. **验证了「不可竞争费 = 外生固定值」的口径**。安全文明施工费在两份文件里
   **都是 7,834.06 元**，投标人未改动它——正是契约 D3 的建模含义。
4. **可作为 T01-00B 解析器与 T01-02C Golden Dataset 的首个真实样本**。

## 四、实测结果

### 4.1 恒等式（报价侧，精确闭合）

```
分部分项 1,264,184.26 + 措施 15,853.12 + 其他 0.00 + 规费 6,528.62 = 1,286,566.00
× 9%   → 增值税 115,790.94        表-12 实测 115,790.94   残差 0.00
× 12%  → 附加税  13,894.91        表-12 实测  13,894.91   残差 0.00
         税金    129,685.85       表-12 实测 129,685.85
         总价  1,416,251.85       表-04 实测 1,416,251.85
```

### 4.2 报价结构：下浮不是单一系数

| 指标 | 值 |
|---|---|
| 限价 Σ(单价×工程量) | 1,374,238.77 |
| 报价 Σ合价 | 1,264,184.26 |
| **加权总下浮率** | **0.919916（下浮 8.008%）** |
| 简单均值 | 0.885459 |
| 中位 | 0.9176 |
| 区间 | 0.8000 – 0.9844 |

逐项下浮比呈**明显分簇**，而非单一系数：

| 下浮比 | 条数 | 典型项目 |
|---|---|---|
| ≈0.810 | 12 | `0402050040xx` 各类标识牌 |
| ≈0.833 | 10 | `03B003`–`03B008` 补充编码的绝缘工器具 |
| ≈0.918 | 13 | 干式变压器、低压开关柜（主体金额） |
| ≈0.921–0.929 | 14 | 高压柜、母线槽、电缆 |
| ≈0.981 / 0.984 | 2 | 整套启动调试、1kV送配电装置系统（调试类，几乎不下浮） |

**这条是建模要优化的核心对象**：报价人对不同费用性质的项目采用不同下浮幅度，
而模型要回答的正是「这一组幅度是否最优」。

### 4.3 限价文件的一处数据质量缺陷

限价文件的**表-04 与表-12 未接上分部分项金额**：其「分部分项工程费」为空，
表-12 的增值税 705.07 只按措施项目费 7,834.06 计得（7,834.06 × 9% = 705.07），
导致该文件合计仅 8,623.74 元，而它逐项单价的合计其实是 1,374,238.77 元。

**结论：限价文件只能提供逐项最高限价（`p_cap`），不能提供限价总价。**
引用时须注意，勿把 8,623.74 当作该项目的招标控制价。

### 4.4 ★ 由此暴露的一条判据陷阱：闭合 ≠ 完整

对限价侧跑 `bidpricing identity-check --side cap`，**全部判据 PASS、残差 0.0000**：

```
分部分项 0.00 + 措施 7,834.06 + 其他 0.00 + 规费 0.00 = 7,834.06
× 9%  → 增值税 705.07   表-12 实测 705.07   ✓
× 12% → 附加税  84.61   表-12 实测  84.61   ✓
         总价  8,623.74  表-04 实测 8,623.74 ✓
```

但它的逐项单价合计是 **1,374,238.77 元**。

也就是说，**恒等式闭合只能证明「已声明的分项彼此自洽」，不能证明「分项齐备」**。
其判定性质与「机制就绪 vs 取值已定」（ADR-0002）同型：都是把两件性质不同的事
混在一个判据上。若把闭合当完整性证据，一张漏掉大部分分项的汇总表会顺利通过全部检查。

据此，完整性必须由**独立判据**承担——即「逐项明细之和 == 表列小计」这类
**输入保真**检查（本模块的 `check_component_sum`），而不是共用恒等式的容差。

## 五、本制品**不**包含什么

- **项目特征**列（技术描述，体量大且含厂商型号）
- **计算基础**文字里引用的中间量（如「分部分项人工费」）——清单不提供人工费分解，
  这也是规费不可复算的原因
- 表-11-1 ~ 表-11-6 明细表（源工作簿中此项目前为空）

## 六、复现方式

源文件为本地 xlsx，提取时经 WorkBuddy 本地编辑器通道读取（`sheet_get_cell_data`
按子表导出 CSV），再按上文列映射归一化。若需重新提取，务必注意：

- **限价文件与报价文件的列数不同**（限价表-09 为 13 列、报价为 14 列），
  但第 10/11 列的含义一致；
- 单元格含**多行文本**（项目特征），必须用引号感知的 CSV 解析，按行号拆分会错位。
